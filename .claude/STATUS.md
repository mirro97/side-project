## 알려진 한계

**능력 설명 424/424 표시, 수치까지 나오는 것은 411개(97%)** — `<!card.trait.statusEffect.…>` 같은 경로는 CSV 참조를 따라가 실제 수치를 채운다(콜트 스피드 부츠 = 13%). 반면 `<VALUE1>` 은 경로 정보가 없고, 카드의 `Value` 에 원값·틱·밀리초가 마커 없이 섞여 있어 복원이 불가능하다("로켓 수가 2050% 늘어납니다"). 그런 자리는 단위째로 자연어로 바꾼다 — "일정 비율 늘어납니다". 상세는 API 레퍼런스 2-5.

**신규 브롤러는 항상 데이터가 늦다** — 한글명, 역할, 사거리, 능력 아이콘이 순차적으로 채워진다. 빌드를 실패시키지 않고 폴백 + 경고로 처리한다.

**전적은 최근 25전이 전부다** — 공식 배틀로그가 그만큼만 준다(실측 고정). 승률·추이를 쌓으려면 DB 와 크론이 필요해서 v1.5 다. 쇼다운 계열은 `result` 없이 `rank` 만 오므로 승패 집계에서 빠진다 — 등수를 승패로 바꾸는 규칙이 모드마다 달라 지어내지 않는다.

**즐겨찾기는 태그만 저장한다** — 이름·아이콘은 바뀌는 값이라 캐시하면 틀린 이름을 보여주게 된다. 목록에는 태그가 그대로 보인다.

**생성 데이터의 게임모드는 로테이션에 실린 12종뿐이다** — 배틀로그에는 `heist`·`megaBoss`·`wipeout`·`lastStand` 처럼 데이터에 없는 모드가 실제로 나온다. 게다가 `modes` 의 영어 이름은 빌드 스크립트가 API 키를 그대로 넣어둔 자리라 번역이 아니다. 그래서 이름은 `lib/game-data.ts` 의 `modeLabel(apiKey, locale)` 하나가 만든다 — 데이터에 있으면 현지화 이름, 없거나 영어가 키 그대로면 키를 다듬어 쓴다(`lastStand` → `Last Stand`). 아이콘은 ID 를 모르므로 자리만 남긴다.

**랭킹은 200위가 상한** — 공식 API 제약. 대부분의 사용자는 자기 계정이 목록에 없다.

**추천 점수는 변별력이 약하다** — 극단적인 설문 답에서는 상위 5명이 89%로 붙는다(실측 스프레드 0.2~7.9p). 숫자는 보조로 두고 축 일치 배지를 주 정보로 쓴다. 브롤러 성향 문구는 아직 벡터에서 뽑은 것뿐이다 — 사전 생성물 636건은 미완.

**종료된 이벤트를 조회할 수 없다** — 공식 API 에 과거 로테이션이 없다. 실측으로도 15슬롯 전부 진행 중이었고 예정·종료가 0개였다.

**이벤트 모디파이어 이름을 다 붙이지 못한다** — 공식 API 의 modifier 문자열과 게임 CSV 의 내부 이름이 갈라져 자동 매칭이 18개 중 9개만 맞았다. 확인된 것만 이름을 붙이고 나머지는 "특수 룰" 로 표시한다. 상세는 API 레퍼런스 2-8.

**프록시 경유 호출은 약 500ms 가 바닥값** — 캐시와 병렬 호출이 선택이 아니라 필수인 이유다.

**Vercel Hobby 는 비상업적 전용** — 수익화하면 Pro 가 필요하다.

## 로컬 환경

```bash
npm run dev          # 개발 서버
npm run build:data   # 게임 데이터 재생성 (BRAWL_STARS_TOKEN 필요)
npm run build        # 프로덕션 빌드. 데이터 생성은 포함하지 않는다
```

커밋 전 세 가지를 모두 돌린다.

```bash
npx tsc --noEmit && npx eslint . && npm test
```

**`~/Documents` 가 iCloud 동기화 대상이라 `RankRow 2.tsx` 같은 충돌 사본이 주기적으로 생긴다.** `.gitignore` 로 커밋은 막았지만 디스크에는 쌓인다. 근본 해결은 레포를 `~/Documents` 밖으로 옮기거나 iCloud 데스크탑·도큐멘트 동기화를 끄는 것이다.
