## 생성 데이터 현황

`npm run build:data` 산출물 기준. **게임 업데이트 때마다 달라지므로 재생성 후 이 표를 갱신한다.**

공식 API·BrawlAPI 외에 `csv_logic` 파일 12개를 읽는다. 능력 설명의 치환자가 CSV 를
건너뛰며 참조하기 때문이다 (목록과 이유는 API 레퍼런스 2-5).

**역할 소스가 바뀌었다.** 예전에는 BrawlAPI 의 `class.name` 을 썼는데 그 필드가 용도를 바꿔

108종 전부 역할이 null 이 되어 역할 필터가 죽는다. `characters` CSV 의 `ClassArchetype` 으로
옮겨 커버리지가 오히려 올랐다 (87/106 → 108/108).

## 알려진 한계

**능력 설명 424/424 표시, 수치까지 나오는 것은 411개(97%)** — `<!card.trait.statusEffect.…>` 같은 경로는 CSV 참조를 따라가 실제 수치를 채운다(콜트 스피드 부츠 = 13%). 반면 `<VALUE1>` 은 경로 정보가 없고, 카드의 `Value` 에 원값·틱·밀리초가 마커 없이 섞여 있어 복원이 불가능하다("로켓 수가 2050% 늘어납니다"). 그런 자리는 단위째로 자연어로 바꾼다 — "일정 비율 늘어납니다". 상세는 API 레퍼런스 2-5.

**신규 브롤러는 항상 데이터가 늦다** — 한글명, 사거리, 능력 아이콘, CDN 초상화가 순차적으로 채워진다. 빌드를 실패시키지 않고 폴백 + 경고로 처리한다. 초상화가 없으면 브롤러 카드가 이니셜을 대신 보여준다 (실제로 COSMO·VINCE 가 404 였다).

**기본 공격·특수 공격 설명은 한국어뿐이다** — 이 문구는 게임 로케일 파일에만 있고 BrawlAPI 에도 영문 엔드포인트에도 없다. 영어 UI 에서는 해당 섹션이 뜨지 않는다. 대신 AI 사용법이 이 설명에 근거해 쓰이므로 영어 사용자도 같은 내용을 다른 형태로 받는다. 초기 8종은 로케일에 키 자체가 없어 프롬프트에서 "공격을 설명하지 말라"는 규칙이 걸린다.

**전적은 최근 25전이 전부다** — 공식 배틀로그가 그만큼만 준다(실측 고정). 승률·추이를 쌓으려면 DB 와 크론이 필요해서 v1.5 다. 쇼다운 계열은 `result` 없이 `rank` 만 오므로 승패 집계에서 빠진다 — 등수를 승패로 바꾸는 규칙이 모드마다 달라 지어내지 않는다.

**즐겨찾기는 태그만 저장한다** — 이름·아이콘은 바뀌는 값이라 캐시하면 틀린 이름을 보여주게 된다. 목록에는 태그가 그대로 보인다.

**생성 데이터의 게임모드는 로테이션에 실린 14종뿐이다** — 배틀로그에는 `heist`·`megaBoss`·`wipeout`·`lastStand` 처럼 데이터에 없는 모드가 실제로 나온다. 게다가 `modes` 의 영어 이름은 빌드 스크립트가 API 키를 그대로 넣어둔 자리라 번역이 아니다. 그래서 이름은 `lib/game-data.ts` 의 `modeLabel(apiKey, locale)` 하나가 만든다 — 데이터에 있으면 현지화 이름, 없거나 영어가 키 그대로면 키를 다듬어 쓴다(`lastStand` → `Last Stand`). 아이콘은 ID 를 모르므로 자리만 남긴다.

**랭킹은 200위가 상한** — 공식 API 제약. 대부분의 사용자는 자기 계정이 목록에 없다.

**추천 점수는 변별력이 약하다** — 극단적인 설문 답에서는 상위 5명이 89%로 붙는다(실측 스프레드 0.2~7.9p). 숫자는 보조로 두고 축 일치 배지를 주 정보로 쓴다. 브롤러 성향 문구는 아직 벡터에서 뽑은 것뿐이다 — 사전 생성물 636건은 `feat/ai-pregen` 에서 작업 중이다.

**종료된 이벤트를 조회할 수 없다** — 공식 API 에 과거 로테이션이 없다. 실측으로도 15슬롯 전부 진행 중이었고 예정·종료가 0개였다.

**이벤트 모디파이어 이름을 다 붙이지 못한다** — 공식 API 의 modifier 문자열과 게임 CSV 의 내부 이름이 갈라져 자동 매칭이 18개 중 9개만 맞았다. 확인된 것만 이름을 붙이고 나머지는 "특수 룰" 로 표시한다. 상세는 API 레퍼런스 2-8.

**프록시 경유 호출은 약 500ms 가 바닥값** — 캐시와 병렬 호출이 선택이 아니라 필수인 이유다.

**Vercel Hobby 는 비상업적 전용** — 수익화하면 Pro 가 필요하다.
