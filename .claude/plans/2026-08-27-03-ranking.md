## 범위

`/{locale}/ranking` 한 페이지. 플레이어 랭킹과 클럽 랭킹을 서브 탭으로 제공한다.

```
  포함    플레이어/클럽 서브 탭 · 국가 선택 · 커서 무한 스크롤 · 1·2·3위 강조
          내 계정 하이라이트 · 200위 상한 안내 · 행 클릭 시 플레이어 요약 패널
  제외    클럽 상세(멤버 목록) · 랭킹 추이 · 즐겨찾기
```

**이미 있는 것을 쓴다.** 홈에서 만든 조각이 대부분 그대로 맞는다.

```
  RankRow          rank · name · trophies · iconUrl · subtitle · nameColor · isMe · onClick
  RankBadge        1·2·3위 금·은·동, 나머지 숫자
  TrophyValue      트로피 아이콘 + 포맷
  useInfiniteList  커서 기반. initial 을 주면 서버 첫 페이지를 그대로 첫 상태로 쓴다
  DetailPanel      화면 폭에 따라 방향이 바뀌는 패널
  RowSkeleton · EmptyState · ErrorState
  getRankingsPlayersApi · getRankingsClubsApi
```

새로 만드는 것은 페이지·목록 컨테이너·라우트 핸들러·플레이어 요약뿐이다.

## 설계 결정

### 서버 첫 페이지는 기본값만 그린다

랭킹은 커서 페이지네이션이라 2페이지부터는 클라이언트가 부른다. 문제는 **첫 페이지를 어떻게 그리냐**다.

`searchParams` 를 서버 컴포넌트에서 읽으면 라우트가 Dynamic 이 되고 `revalidate` 가 무시된다. 홈에서 이미 겪었고 브롤러에서도 `useSearchParams` 하나 때문에 그리드 전체가 클라이언트로 밀렸다. 프록시 왕복이 500ms 바닥이라 이걸 매 방문자가 내면 안 된다.

```
  서버    기본값(global · players) 첫 페이지만 렌더. revalidate 600 으로 정적 유지
  클라    kind·country 가 기본값과 다르면 그때 /api/ranking 을 부른다
```

`useInfiniteList(load, initial)` 가 이 구조를 이미 지원한다. 기본값이면 `initial` 을 넘겨 서버 결과를 그대로 첫 상태로 쓰고, 아니면 `initial` 없이 마운트 시 첫 페이지를 부른다.

**공유 데이터라 캐시가 붙는다.** 랭킹은 대표 계정과 무관하므로 라우트 핸들러의 상류 호출에 10분 캐시를 건다. 캐시 경계 규칙(컨벤션 1-5) 그대로다.

### 서브 탭과 국가는 로컬 상태다 (구현 중 뒤집음)

처음에는 탭·국가도 URL 에 두려 했다. 공유와 뒤로 가기 때문이다. **구현하고 빌드 산출물을 재보니 틀린 선택이었다.**

```
  URL 방식     프리렌더 HTML 안의 랭킹 행  0개   (스켈레톤만)
  로컬 상태     프리렌더 HTML 안의 랭킹 행  30개  (브롤러와 동일)
```

목록이 `kind`·`country` 에 의존하므로 URL 에 두면 목록도 `useSearchParams` 아래로 들어간다. 그러면 서버가 받아온 첫 페이지가 통째로 버려지고 방문자가 500ms 프록시 왕복을 다시 낸다. Suspense 로 격리해도 소용없다 — 격리할 수 있는 건 파라미터에 의존하지 않는 부분뿐이다.

```
  로컬 상태     kind · country          목록이 서버 렌더를 그대로 쓴다
  URL          player                  패널만. 공유되고 뒤로 가기로 닫힌다
```

브롤러 페이지와 같은 규칙이다 — 필터는 로컬, 상세는 URL. **`?kind=clubs` 공유 링크는 포기했다.** 첫 화면 속도와 맞바꿨다.

### 목록 컴포넌트는 종류를 파라미터로 받는다

두 응답이 거의 같다. 다른 건 세 가지뿐이다.

```
              플레이어                   클럽
  아이콘      icon.id (플레이어 아이콘)    badgeId (클럽 배지)
  부제        club.name                 memberCount
  이름 색상    nameColor (ARGB)          없음
```

`RankingList` 하나에 `kind` 를 넘기고, 행을 `RankRow` 로 변환하는 매퍼만 종류별로 둔다. v2 에서 클럽 상세를 붙일 때 이 구조가 그대로 쓰인다.

### 200위는 구현 한계가 아니라 API 한계다

`paging.cursors` 가 빈 객체로 오는 게 종료 신호다. 실측으로 확인했다.

```
  limit=200            items 200개, 마지막 rank 200, paging.cursors {}   ← 종료
  limit=30 → after     2페이지 rank 31~60, 커서 계속 나옴
  커서 형태             "eyJwb3MiOjN9"  (불투명 토큰. 직접 만들지 않는다)
```

`useInfiniteList` 는 `nextCursor` 가 없으면 끝으로 본다. 목록 하단에 상한을 명시해서 "왜 더 안 나오지"를 만들지 않는다.

내 계정이 200위 밖이면 하이라이트할 대상이 아예 없다. 목록을 다 훑고 나서 안내하면 늦으므로, **대표 계정이 있고 목록에 없으면** 하단 상한 문구에 함께 붙인다.

### 행 클릭은 플레이어 요약 패널을 연다

설계서 2-5 의 "클릭 시 상세 패널" 요구다. 프로필 페이지(플랜 06)와 겹치지만, 패널은 요약이고 페이지는 전체라 역할이 다르다.

`/api/player/[tag]` 가 이미 있고 `MyAccountCard` 가 같은 응답으로 트로피·클럽·대표 브롤러를 그린다. **표시 부분만 `PlayerSummary` 로 떼어** 홈 카드와 랭킹 패널이 같은 것을 쓴다. 플랜 06 도 이걸 쓴다.

클럽 행은 클릭해도 열지 않는다. `/clubs/{tag}` 는 v2 범위다.

### 국가 코드는 목록을 고정한다

공식 API 는 국가 코드를 검증하지 않는다. **잘못된 코드도 `200` 에 빈 목록으로 온다** (실측: `ZZ`·`XX` → `items` 0개). 에러가 아니라 조용한 빈 화면이라 오히려 더 나쁘다.

드롭다운 목록을 코드에 고정하고, 그 외 값은 라우트 핸들러가 `400` 으로 막는다. 그래야 UI 가 "데이터 없음"과 "잘못된 입력"을 구분해 안내할 수 있다. 대소문자는 API 가 가리지 않지만(`kr` = `KR`) 우리는 대문자로 정규화해 캐시 키를 하나로 만든다.

```
  global(기본) · KR · US · JP · DE · GB · FR · BR · MX · ES
```

해외 타겟이므로 `global` 이 기본이다. 목록은 사용자 분포를 보고 조정한다.

# Tasks

### Task 1: 순수 함수 (`src/lib/ranking.ts`)

테스트가 가능한 부분을 먼저 분리한다. 네트워크도 React 도 닿지 않는다.

```ts
export const RANKING_KINDS = ['players', 'clubs'] as const
export type RankingKind = (typeof RANKING_KINDS)[number]

/** 공식 API 가 국가 코드를 검증하지 않아 잘못된 값도 빈 목록으로 온다. 목록을 고정한다 */
export const COUNTRIES = ['global', 'KR', 'US', 'JP', 'DE', 'GB', 'FR', 'BR', 'MX', 'ES'] as const

export function isRankingKind(v: string): v is RankingKind
export function isCountry(v: string): boolean

/** 응답 한 건을 RankRow 가 받는 모양으로 바꾼다 */
export function toRankRow(kind, entry, locale): RankRowProps

/** paging.cursors 가 빈 객체면 끝이다 */
export function nextCursorOf(paged: Paged<unknown>): string | undefined
```

테스트: 종류별 매핑(아이콘 URL·부제·nameColor), 빈 `cursors` → `undefined`, 잘못된 kind·country 거부, 클럽 부제의 멤버 수 포맷.

### Task 2: 메시지 추가

`messages/{ko,en}.json` 에 `ranking` 네임스페이스를 만든다.

```
  title          랭킹 / Rankings
  tabPlayers     플레이어 / Players
  tabClubs       클럽 / Clubs
  country        국가 / Country

  members        멤버 {count}명 / {count} members
  limitNotice    상위 200위까지 제공됩니다 / Top 200 only
  notRanked      내 계정은 200위 밖입니다 / Your account is outside the top 200
  loadMore       더 보기 / Load more
```

### Task 3: 라우트 핸들러 (`/api/ranking/[kind]`)

```ts
export async function GET(req, { params }) {
  const { kind } = await params
  const country = searchParams.get('country') ?? 'global'
  const after = searchParams.get('after') ?? undefined
  // 커서는 불투명 토큰이다. 검증하거나 재생성하지 않고 그대로 넘긴다
  ...
}
```

- `kind`·`country` 를 검증해 잘못된 값은 `400`. 외부 API 를 때리지 않는다
- 응답은 `ApiResult<T>` 형태 (컨벤션 1-4)
- **커서는 손대지 않는다.** 직접 만들면 `400` 이 난다
- 상류 호출에 10분 캐시. 공유 데이터라 방문자마다 프록시를 때릴 이유가 없다

`getRankingsPlayersApi` / `getRankingsClubsApi` 가 캐시 옵션을 받도록 `bsFetch` 의 `init` 을 넘기는 자리를 연다. 플레이어 조회는 캐시하지 않는다 — 대표 계정마다 다르다.

### Task 4: `PlayerSummary` 추출

`MyAccountCard` 에는 테스트가 없다. "기존 테스트가 계속 통과해야 한다"는 기준을 쓸 수 없으므로, 뗀 뒤 홈 화면이 그대로인지 눈으로 확인한다.

`MyAccountCard` 에서 **표시 부분만** 뗀다. 데이터 조회(`useQuery`)와 대표 계정 분기는 카드에 남긴다.

```tsx
export function PlayerSummary({ player, locale }: { player: Player; locale: Locale })
```

트로피 · 최고 트로피 · 3대3 승리 · 클럽명 · 대표 브롤러(트로피 최고). 홈 카드와 랭킹 패널이 같은 것을 쓴다.

기존 `MyAccountCard` 테스트가 계속 통과해야 한다. 통과하지 않으면 뗀 범위가 잘못된 것이다.

### Task 5: `RankingList`

```tsx
<RankingList kind country initial locale onSelect />
```

- `useInfiniteList(load, initial)`. `initial` 은 기본값일 때만 들어온다
- 로더는 `/api/ranking/{kind}?country=&after=` 를 부르고 `nextCursorOf` 로 커서를 뽑는다
- 대표 계정 태그와 같은 행에 `isMe`
- 하단: 로딩 중이면 `RowSkeleton`, 끝났으면 `limitNotice`(+ 필요하면 `notRanked`)
- 빈 목록·에러는 `EmptyState` · `ErrorState`

더 받기는 브롤러와 같은 **버튼** 방식이다. 브롤러가 IntersectionObserver 가 아니라 "더 보기" 버튼을 쓰고 있어 맞췄다.

### Task 6: `RankingBrowser`

서브 탭 · 국가 드롭다운 · 목록을 묶는다. `useSearchParams` 를 쓰므로 클라이언트 컴포넌트이고, **페이지에서 Suspense 로 감싼다.**

- 탭·국가 변경은 `router.replace` 로 URL 만 바꾼다. 목록은 파라미터 변화에 반응한다
- 국가 드롭다운은 브롤러 정렬에서 쓴 shadcn `Select` 를 그대로 쓴다 (네이티브 `<select>` 는 위치가 어긋난다)

### Task 7: 페이지 연결

```tsx
export const revalidate = 600
export function generateStaticParams() { ... }   // 없으면 Dynamic 으로 잡혀 revalidate 가 죽는다
```

서버에서 기본값(global · players) 첫 페이지를 가져와 `RankingBrowser` 에 `initial` 로 넘긴다. 실패해도 페이지는 그린다 — `ErrorState` 를 목록 자리에 둔다.

`PlayerPanelSlot` 은 별도 Suspense 로 감싼다. 브롤러에서 이걸 안 해서 그리드 전체가 클라이언트로 밀렸다.

## 완료 조건

```
  □ /ko/ranking · /en/ranking 이 서버에서 렌더된다 (빌드 출력에서 ○ 또는 ISR)
  □ 스크롤로 200위까지 이어지고, 그 뒤에는 상한 문구가 뜬다
  □ 클럽 탭으로 클럽 랭킹이 나온다
  □ 패널을 열면 URL 에 남고, 뒤로 가기로 닫힌다
  □ 국가를 바꾸면 목록이 갈아끼워진다 (이어붙지 않는다)
  □ 대표 계정이 목록에 있으면 하이라이트, 없으면 200위 밖 안내
  □ 플레이어 행 클릭 시 요약 패널, 클럽 행은 열리지 않는다
  □ 잘못된 kind·country 로 /api/ranking 을 부르면 400
  □ npx tsc --noEmit && npx eslint . && npm test 통과
  □ 콘솔 에러 0
```
