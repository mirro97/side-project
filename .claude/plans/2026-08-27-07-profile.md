## 왜 지금 이걸 하나

**이미 만든 기능 세 개가 도달 불가 상태다.** `setMainAccount` 을 호출하는 화면이 없고 `/{locale}/profile` 라우트도 없어서, 헤더 아바타와 홈 [내 계정 설정] 이 **404 로 간다.**

```
  홈 내 계정 카드          항상 "대표 계정을 설정하면…" 빈 상태
  랭킹 [내 계정] 하이라이트  절대 안 뜸
  브롤러 보유 진행도        절대 안 뜸
  추천 계정 벡터 혼합       절대 안 됨 — 2그룹 분리도 함께 죽는다
```

프로필 하나로 넷이 전부 풀린다. 새 기능을 더하는 게 아니라 **이미 지불한 비용을 회수하는 작업**이다.

## 범위

`/{locale}/profile` 한 페이지.

```
  포함    태그 조회 · 대표 계정 지정/해제 · 즐겨찾기 태그 · 계정 요약
          보유 브롤러 그리드 · 최근 전투 목록
  제외    트로피 추이 그래프(v1.5 · DB 필요) · 전적 축적 · 클럽 상세
```

**탭바에 넣지 않는다.** `tabs.ts` 에 "모바일 하단 탭바 5개 상한"이 이미 적혀 있고, 상단바 아바타가 진입점이다.

## 실측으로 확인한 것 — 최근 전투는 v1 에 넣는다

플랜 05 는 배틀로그를 "v1.5 (전적 축적과 함께)"로 미뤄뒀다. **그 판단은 최근 전투 목록에는 적용되지 않는다.** 두 가지가 섞여 있었다.

```
  전적 축적       시간에 걸쳐 스냅샷을 쌓는 것      → DB 필요. v1.5 가 맞다
  최근 전투 목록   API 가 주는 25전을 그대로 보여줌   → DB 불필요
```

실제로 불러 확인했다.

```
  GET /players/{tag}/battlelog     25전 고정
  battle 키    mode · type · result · trophyChange · duration · starPlayer · teams
  event 키     id · map · mode · modeId
  실측 계정 A   25전 전부 result·trophyChange 있음 (brawlBall)
  실측 계정 B   25전 (wipeout) — rank·players 키 없음
```

**파서와 타입이 이미 있고 테스트도 붙어 있다.** 공통 기반에서 만들어 뒀다.

```
  src/lib/bs/parse.ts      parseBattle(item, myTag) → ParsedBattle | null
  src/types/api.ts         ParsedBattle (mode·map·brawlerId·result·rank·trophyChange·isStarPlayer)
  parse.test.ts            팀 모드 · 쇼다운 평면 배열 · 모르는 구조 → null · 미참여 → null
```

없는 건 API 래퍼 하나뿐이다. 코드 리뷰 때 "호출되지 않는 래퍼는 두지 않는다"는 규칙으로 `getPlayerBattlelogApi` 를 지웠는데, 이제 호출부가 생기므로 되살린다.

**쇼다운 계열을 실측 표본에서 못 봤다.** 두 계정 모두 팀 모드만 나왔다. 파서는 쇼다운 경로를 테스트로 덮고 있으니 코드는 준비돼 있지만, 화면에서 `rank` 표시를 실제 응답으로 확인하지 못한 상태다 — 구현 중에 쇼다운을 도는 계정으로 한 번 더 본다.

## 설계 결정

### 조회는 클라이언트가 한다

태그는 사용자가 입력하고 대표 계정은 로컬스토리지에 있다. **서버가 알 수 있는 게 없으므로 페이지는 정적 셸이고 조회는 전부 클라이언트다.** 추천 페이지와 같은 구조다.

`usePlayer(tag)` 가 이미 있다. 랭킹 패널·홈 카드·추천이 쓰는 것과 같은 훅이라 같은 태그면 요청이 합쳐진다.

### 조회 대상 태그는 URL 에 둔다

```
  /ko/profile              대표 계정 (없으면 입력 폼)
  /ko/profile?tag=%23ABC   특정 계정 조회 — 공유 가능
```

랭킹의 `?player=` 와 같은 이유다. 다만 **랭킹에서 배운 것을 반복하지 않는다** — 목록이 파라미터에 의존하면 정적 렌더가 죽는다. 이 페이지는 어차피 서버가 그릴 게 없어 해당하지 않지만, `useSearchParams` 를 쓰는 부분은 그대로 Suspense 로 감싼다.

### 대표 계정 지정은 되돌릴 수 있게 만든다

설계서 문구를 그대로 따른다.

```
  지정 전     [내 계정으로 지정] 버튼
  모달        "해당 계정을 대표 계정으로 설정할까요?"
              기존 대표 계정이 있으면 "기존 대표 계정을 덮어씁니다" 한 줄 추가
              [취소] [확인]
  지정 후     [대표 계정] 배지 + [해제] 버튼
```

**모달은 `DetailPanel` 을 쓰지 않는다.** 그건 드로어고 이건 확인 대화다. shadcn `Dialog` 를 새로 받는다 — 코드 리뷰에서 지웠지만 이번엔 실제 호출부가 있다.

### 즐겨찾기는 태그만 저장한다

`Settings.favoriteTags: string[]` 이 이미 있다. 이름·아이콘은 저장하지 않는다 — 바뀌는 값이라 캐시하면 틀린 이름을 보여주게 된다. 목록에서 태그를 누르면 그 태그로 조회한다.

대표 계정과 즐겨찾기는 **별개다.** 대표는 하나, 즐겨찾기는 여럿.

### 보유 브롤러 그리드는 만들지 않고 링크한다

설계서에 "보유 브롤러 그리드 — 정렬·필터"가 있는데, **브롤러 페이지가 이미 그걸 한다.** 대표 계정이 있으면 브롤러 페이지가 보유 진행도를 얹어 보여준다(플랜 02).

프로필에는 **요약만** 둔다 — 보유 수 / 106, 최고 트로피 브롤러 셋. 자세히 보려면 브롤러 탭으로 보낸다. 같은 그리드를 두 번 만들 이유가 없다.

### 표시 항목은 이미 있는 컴포넌트를 쓴다

`PlayerSummary` 가 트로피·최고·레벨·대표 브롤러를 그린다(홈 카드·랭킹 패널이 공유). 프로필은 여기에 **승수와 클럽**을 더한 확장이 필요하다.

`PlayerSummary` 를 고치면 홈 카드가 함께 커진다. **프로필 전용 블록을 옆에 두고 `PlayerSummary` 는 그대로 둔다** — 홈은 좁은 섹션이라 지금 크기가 맞다.

## 완료 조건

```
  □ /ko/profile · /en/profile 이 SSG 로 잡힌다 (더 이상 404 가 아니다)
  □ 헤더 아바타와 홈 [내 계정 설정] 이 정상 이동한다
  □ 태그를 넣으면 계정이 조회되고, 잘못된 문자는 API 호출 없이 걸러진다
  □ [내 계정으로 지정] → 모달 → 확인하면 상단바 아바타가 바뀐다
  □ 기존 대표 계정이 있으면 모달에 덮어쓴다는 안내가 나온다
  □ 해제하면 홈 카드가 빈 상태로 돌아간다
  □ 즐겨찾기 추가·삭제가 새로고침 후에도 유지된다
  □ 최근 전투 25전이 모드·맵·결과·트로피 변동과 함께 나온다
  □ 대표 계정 지정 후 랭킹 하이라이트·브롤러 진행도·추천 2그룹이 살아난다  ← 이 플랜의 목적
  □ npx tsc --noEmit && npx eslint . && npm test 통과
  □ 콘솔 에러 0 (하이드레이션 경고 포함)
```

마지막에서 두 번째 항목이 핵심이다. 프로필 자체보다 **잠겨 있던 기능이 열리는지**가 이 플랜의 성공 기준이다.
