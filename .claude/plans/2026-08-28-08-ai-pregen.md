## 실측으로 확인한 것

### 생성은 검색 쿼터를 쓰지 않는다

지금 Gemini 검색 그라운딩이 429 로 막혀 있다. **이 작업은 거기 걸리지 않는다** — 우리가 가진 데이터(스탯·능력 설명·기어)를 프롬프트에 넣고 모델은 문장만 쓴다. 검색 도구를 켜지 않으므로 그라운딩 할당량과 무관하다.

설계서 2-8 의 "AI가 추천 자체를 하지 않는다. AI는 설명만 쓴다" 가 그대로 여기 적용된다.

### 구조화 출력 필드 이름

`generateContent` 의 JSON 강제는 **`generationConfig.responseFormat.text.{mimeType, schema}`** 다. `responseMimeType` / `responseSchema` 를 따로 두는 옛 형태가 아니다 (2026-08-28 문서 확인).

다만 **이 필드에 의존하지 않는다.** 모델·엔드포인트가 빠르게 바뀌는 영역이고 키가 없어 실제 응답을 확인할 수 없다. 요청에는 넣되, 파싱은 코드펜스를 벗기고 `JSON.parse` 하는 방어적 경로를 따로 둔다. 형식이 어긋나면 그 브롤러만 건너뛴다.

### 호출 수를 106 회로 줄인다

```
  636 회   항목마다 한 번            낭비
  212 회   브롤러 × 로케일           ko/en 이 서로 다른 내용을 쓸 수 있다
  106 회   브롤러당 한 번, 6필드 응답  ← 이걸 쓴다
```

한 응답에 ko·en 을 함께 받으면 **두 언어가 같은 내용을 말한다는 게 보장된다.** 따로 부르면 한글은 "부쉬에서 기습" 이라 쓰고 영어는 다른 전략을 쓰는 일이 생긴다.

## 설계 결정

### 파일은 두 갈래로 나눈다

설계서는 `public/data/ai/{locale}/{id}.json` 하나만 말하는데, **추천 화면이 그것만으로는 못 쓴다.** 결과 카드가 최대 10장이라 파일 10개를 받아야 한다.

```
  public/data/ai/{locale}/{id}.json   상세용. 사용법·기어·성향 전체 (건당 ~3KB)
                                      상세 패널을 열 때 한 장만 받는다

  src/data/ai-traits.generated.json   추천용. id → { en, ko } 한 줄씩
                                      번들에 들어간다. 106종이라 네트워크 0회
```

같은 생성 결과에서 두 산출물을 뽑는다. 성향 한 줄은 짧아서 106종 전부 번들에 넣어도 부담이 없다.

### 스크립트는 중단·재개가 되어야 한다

무료 티어의 일일 한도가 106 회를 못 버틸 수 있다. **이미 파일이 있는 브롤러는 건너뛴다.** 한도가 차면 다음 날 다시 돌려 이어서 채운다.

```bash
npm run build:ai            # 없는 것만 생성
npm run build:ai -- --force # 전부 다시
npm run build:ai -- --id 16000000  # 한 종만 (검토 후 재생성용)
```

429 를 만나면 백오프하고, 연속으로 막히면 **거기서 멈춘다.** 끝까지 밀어붙이면 실패 로그만 106줄 남는다.

### 사람이 고칠 수 있어야 한다

설계서가 DB 대비 이점으로 꼽은 지점이다. 출력은 들여쓴 JSON 으로 커밋하고, 스크립트는 **기존 파일을 함부로 덮지 않는다**(`--force` 없이는). AI 가 틀린 문장을 쓰면 파일을 고쳐 커밋하면 되고, 다음 실행이 그걸 지우지 않는다.

### 파일이 없으면 섹션을 그리지 않는다

플랜 02 의 규칙 그대로다. 생성이 절반만 됐어도 화면은 깨지지 않는다. 로딩 실패도 같다 — 에러를 띄우지 않고 섹션만 빠진다. 설계서 2-8 의 "AI 가 실패해도 규칙 기반 결과는 그대로 노출한다".

### 추천 카드는 대체가 아니라 우선순위다

성향 문구가 있으면 그걸 쓰고, 없으면 지금의 벡터 기반 문구를 그대로 쓴다. 106종이 다 차기 전에도 화면이 일관되게 동작한다.

# Tasks

### Task 1: 타입과 로더

```ts
export interface AiContent {
  /** 브롤러 사용법 2~3문장 */
  howToPlay: string
  /** 추천 기어와 이유. 기어 이름은 우리 데이터에 있는 것만 */
  gears: string
  /** 어떤 성향의 사람에게 맞는지 한 줄. 특정 사용자를 언급하지 않는다 */
  trait: string
}
```

`getAiTraits()` 는 번들된 생성물에서 읽고, `fetchAiContent(locale, id)` 는 `public/` 파일을 받는다. 없으면 `null` — 던지지 않는다.

테스트: 생성물이 없어도 `null` 을 준다 · 트레이트 조회가 없는 id 에 `undefined`.

### Task 2: 프롬프트 (`scripts/ai-prompt.ts`)

브롤러 하나의 실제 데이터를 넣고 6필드를 받는다.

```
  넣는 것   이름(en/ko) · 역할 · 희귀도 · HP·속도·사거리
            스타파워·가젯 이름과 설명 · 사용 가능 기어 목록
  받는 것   howToPlay/gears/trait × en/ko
```

규칙은 채팅 프롬프트와 같은 원칙을 따른다 — **주어진 데이터 밖을 지어내지 않는다.** 기어는 목록에 있는 것만, 수치는 준 것만.

테스트: 6필드를 요구한다 · 능력 설명이 없는 브롤러도 이름은 들어간다 · 기어 목록이 프롬프트에 있다.

### Task 3: 생성 스크립트

`build:data` 와 같은 모양으로 만든다. `.env.local` 의 `GEMINI_API_KEY` 를 읽고, 없으면 즉시 실패한다.

- 브롤러 순회 → 파일 있으면 skip → 호출 → 파싱 → 두 로케일 파일 쓰기
- 호출 간 지연을 둔다. 429 는 백오프 후 재시도, 연속 실패면 중단
- 끝나면 `ai-traits.generated.json` 을 다시 만든다
- 요약 로그: 생성 n · 건너뜀 n · 실패 n

### Task 4: 브롤러 상세 두 섹션

`BrawlerDetail` 에 사용법·추천 기어를 넣는다. 파일이 없으면 섹션 자체를 그리지 않는다.

상세 패널은 이미 클라이언트 컴포넌트이므로 열릴 때 받는다. 같은 브롤러를 다시 열면 react-query 가 합친다.

### Task 5: 추천 카드 문구

`ResultList` 의 `useReason` 이 트레이트를 먼저 보고, 없으면 지금 로직으로 떨어진다.

### Task 6: 메시지

```
  brawlers.howToPlay · brawlers.recommendedGears
```

## 완료 조건

```
  □ npm run build:ai 가 키 없이 실행되면 명확한 오류로 멈춘다
  □ 중단 후 다시 돌리면 이미 만든 것을 건너뛴다
  □ 사람이 고친 파일을 --force 없이 덮지 않는다
  □ 생성물이 0건이어도 브롤러 상세·추천이 지금과 똑같이 동작한다
  □ 생성물이 있으면 상세에 사용법·추천 기어가 뜨고 추천 카드 문구가 바뀐다
  □ 존재하지 않는 기어 이름이 본문에 없다 (표본 검수)
  □ npx tsc --noEmit && npx eslint . && npm test 통과
```

**마지막에서 세 번째가 이 플랜의 안전장치다.** 생성이 한 건도 안 된 상태로 배포해도 아무것도 깨지지 않아야 한다.
