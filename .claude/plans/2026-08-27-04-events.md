## 범위

`/{locale}/events` 한 페이지. 현재 로테이션 중인 슬롯을 종료 임박순으로 보여준다.

```
  포함    15슬롯 종료 임박순 · 모드 필터 · 맵 이미지 · 로컬 타임존 종료 시각
          1분 간격 카운트다운 · 만료 슬롯 제거 · 전부 만료 시 재조회
  제외    예정/종료 이벤트 · 맵 승률 통계 · 즐겨찾기
```

**이미 있는 것을 쓴다.**

```
  CountdownTimer   1분 간격 갱신, 2시간 미만이면 경고색, 만료 시 onEnded
  EventRow         홈의 이벤트 행 (아이콘 · 모드명 · 맵명 · 카운트다운)
  FilterChips      브롤러의 역할 칩. key·label·count 를 받는다
  sortByEndingSoon 종료 임박순 + 이미 끝난 슬롯 제외
  parseBrawlTime   20260826T080000.000Z 전용 파서
  getMode          modeId → 현지화된 모드명 + imageId
  EmptyState · ErrorState
```

---

## 실측으로 확인한 것

플랜을 쓰기 전에 `GET /events/rotation` 을 직접 불러 확인했다.

```
  슬롯 수          15개
  상태             진행중 15 / 예정 0 / 종료 0        ← 설계서의 한계가 사실이다
  모드 매칭         12/12 전부 생성 데이터와 매칭
  맵 이미지         cdn.brawlify.com/maps/regular/{event.id}.png → 200
  modifiers 보유    15슬롯 중 2개
  시각 형식         20260826T080000.000Z (UTC)
```

**예정 이벤트가 아예 없다.** 응답에는 지금 돌고 있는 슬롯만 담긴다. "다음 로테이션"을 보여줄 방법이 없으므로 화면에 그런 자리를 만들지 않는다.

## 설계 결정

### 모드 필터는 로컬 상태다

랭킹에서 배운 그대로다. 목록이 필터 값에 의존하므로 URL 에 두면 `useSearchParams` 가 목록을 덮어 서버 렌더가 버려진다. 브롤러의 역할 칩과 같은 방식으로 로컬 상태로 둔다.

이 페이지에는 URL 에 둘 상세도 없다 — 이벤트는 클릭해서 열 것이 없다. **Suspense 경계 자체가 필요 없다.**

### 만료는 클라이언트가 처리한다

30분 캐시가 걸린 정적 페이지라, 사용자가 보는 동안 슬롯이 끝날 수 있다. 실제로 15슬롯 중 하나는 2시간짜리였다.

```
  CountdownTimer 가 만료를 알린다  →  그 슬롯을 목록에서 뺀다
  목록이 비면                      →  /api/events 로 로테이션을 다시 받는다
```

`onEnded` 콜백이 이미 있다. 새 컴포넌트를 만들 필요가 없다.

### 종료 시각은 로컬 타임존으로 보여준다

해외 사용자가 주 타겟이라 UTC 를 그대로 노출하면 안 된다. `parseBrawlTime` 이 만든 `Date` 를 `toLocaleString(locale)` 으로 찍는다.

**서버와 클라이언트의 타임존이 다르면 하이드레이션이 어긋난다.** 시각 문자열은 클라이언트에서만 만든다 — 서버 렌더에서는 카운트다운과 같은 자리에 아무것도 넣지 않는다.

### 모디파이어 이름은 확인된 것만 보여준다

공식 API 의 modifier 문자열과 게임 CSV 의 내부 이름이 갈라진다. 정규화 매칭으로는 **18개 중 9개만 맞았다.**

```
  angryRobo      →  CSV BigRobo            ❌ 이름이 다르다
  meteorShower   →  CSV Meteors            ❌
  graveyardShift →  CSV LifeLeech          ❌
  superCharge    →  CSV FastSuperCharge    ❌
  showdown+      →  CSV 에 없음             ❌ (로케일에는 TID_EVENT_MODIFIER_15 = "쇼다운+")
  unknown        →  API 가 모르는 신규 모디파이어
```

이름을 추측해서 붙이면 틀린 이름을 보여주게 된다. **브롤러 TID 를 추측했다가 4개 전부 틀린 적이 있다.** 같은 실수를 하지 않는다.

```
  none · unknown       배지를 붙이지 않는다
  확인된 매핑           현지화된 이름을 배지로 (표에 있는 것만)
  그 외                "특수 룰" 배지 — 정보는 남기고 이름은 지어내지 않는다
```

확인된 매핑은 로케일 값과 눈으로 대조한 것만 표에 넣는다. 표는 실제 로테이션에서 새 값이 보일 때 늘린다.

### 캐시는 30분이다

로테이션은 시간 단위로 바뀐다. 설계서의 캐시 경계 그대로 `revalidate = 1800`. 만료 재조회용 `/api/events` 는 라우트 핸들러로 두되, 상류 호출은 같은 30분 캐시를 탄다.

# Tasks

### Task 1: 순수 함수 (`src/lib/events.ts`)

```ts
/** 화면이 바로 쓸 수 있는 모양 */
export interface EventView {
  slotId: number
  modeId: number
  modeName: LocalizedText | null
  modeIconUrl: string
  mapName: string
  mapImageUrl: string
  end: Date
  modifiers: string[]      // 표시할 배지 라벨. 없으면 빈 배열
}

export function toEventViews(slots: EventSlot[], now?: Date): EventView[]
export function countByMode(views: EventView[]): Record<number, number>
export function filterByMode(views: EventView[], modeId: number | null): EventView[]
```

- 정렬과 만료 제외는 `sortByEndingSoon` 을 그대로 쓴다
- 맵 이미지: `https://cdn.brawlify.com/maps/regular/{event.id}.png`
- 모드 아이콘: `getMode(modeId).imageId` — **`modeId` 를 그대로 넣으면 404 다**

모디파이어는 별도 함수로 둔다.

```ts
/** 로케일 값과 눈으로 대조한 것만 넣는다. 추측 금지 */
const VERIFIED_MODIFIERS: Record<string, LocalizedText> = {
  // TID_EVENT_MODIFIER_15 — texts: "SHOWDOWN+", kr: "쇼다운+"
  'showdown+': { en: 'Showdown+', ko: '쇼다운+' },
}
export function modifierLabels(raw: string[] | undefined): { name?: LocalizedText }[]
```

TID 를 들고 다니다 화면에서 로케일을 조회하려 했는데, **런타임에는 게임 로케일이 없다** (번들에 든 건 생성 데이터뿐이다). 그래서 표가 양쪽 언어 문자열을 직접 들고 있다. 영문은 `localization/texts`, 한국어는 `localization/kr` 에서 확인했다.

테스트: 종료 임박순 정렬, 만료 슬롯 제외, 모드별 개수, `none`·`unknown` 이 배지를 만들지 않는 것, 미확인 값이 generic 으로 떨어지는 것, 맵·아이콘 URL 형태.

### Task 2: 메시지 추가

```
  title          이벤트 / Events
  allModes       전체 / All
  specialRule    특수 룰 / Special rule
  endsAt         종료 / Ends
  empty          진행 중인 이벤트가 없습니다 / No events running
```

모디파이어 이름은 게임 로케일에서 오므로 메시지 파일에 넣지 않는다.

### Task 3: 라우트 핸들러 (`/api/events`)

만료 후 재조회 전용이다. `ApiResult<EventSlot[]>` 형태로 내린다. 상류 호출은 이미 `getEventsRotationApi` 가 30분 캐시를 타고 있다.

### Task 4: `EventTime`

```tsx
<EventTime end={end} locale={locale} />
```

`toLocaleString` 결과는 타임존에 따라 달라진다. **마운트 전에는 아무것도 그리지 않는다** — 서버가 만든 문자열과 클라이언트가 만든 문자열이 다르면 하이드레이션 경고가 난다.

구현에서는 `useEffect` + `setState` 가 아니라 `useSyncExternalStore` 를 쓴다. 전자는 `react-hooks/set-state-in-effect` 에 걸린다 (`useMediaQuery` 와 같은 방식).

### Task 5: `EventCard`

맵 이미지를 배경으로 깔고 그 위에 모드 아이콘·모드명·맵명·카운트다운·모디파이어 배지를 얹는다. 이미지가 없거나 404 면 배경 없이 그린다 (능력 아이콘에서 쓴 `onError` 폴백과 같은 방식).

### Task 6: `EventBrowser`

- 모드 칩으로 필터 (로컬 상태)
- `CountdownTimer` 의 `onEnded` 로 만료 슬롯 제거
- 남은 슬롯이 0이면 `/api/events` 재조회
- 재조회도 비면 `EmptyState`

### Task 7: 페이지 연결

```tsx
export const revalidate = 1800
export function generateStaticParams() { ... }
```

서버에서 로테이션을 받아 `EventBrowser` 에 넘긴다. 실패하면 `ErrorState`.
